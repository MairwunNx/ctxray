# Changelog

The “Release” workflow takes the notes for a version from its section here, unless you type them into its `changelog` field.

## 0.1.1

L1 now catches the files a harness silently skips, and the secrets nobody meant to give a model. Every check here was confirmed on the harnesses themselves, on macOS and Linux.

- 🔤 **Files named almost right.** `misnamed-file` names the file a harness looks for when yours is `AGENT.md`, `.cursorrule`, `.claude/rule/`, a skill as a lone `.md` file, or `mcp.json` in the root. `letter-case` catches `claude.md` and `skill.md`: macOS and Windows read them, Linux CI doesn't.
- 🔑 **Secrets in agent files.** `secret` and `personal-data` find keys, tokens, passwords, emails, and phone numbers in the files the model reads, with ctxray's redactor and the gitleaks rules. A finding names the kind and the line, never the value.
- 🏠 **Paths only you have.** `absolute-path` flags `/Users/…`, `~/…`, and `C:\…` in imports, links, globs, and MCP configs. `not-shared` names agent files that `.gitignore` hides, that aren't committed yet, or that sit behind a symlink out of the repository, and `broken-symlink` a link that points nowhere.
- 🧭 **inspect sees what the harnesses see.** Skills in subfolders for Codex, OpenCode, and Cursor. Cursor and OpenCode skip a skill without a description, Codex one with a byte order mark or tabs in its frontmatter. Cursor reads `.MDC` rules, and `alwaysApply: "true"` gets a warning. A Mac now reads a project the way Linux CI does.
- 📊 **The Loadout inside Claude Code.** The plugin draws a row above the prompt: a bar of what the context is made of, its total, and its share of the window. `/ctxray-loadout` opens a pane with every share, the instruction files and the `@` imports that brought them, MCP servers, and skills, each with the tokens Claude Code itself counted. Keys 1–4 switch the tabs. It needs Claude Code 2.1.286 or newer, and speaks English and Russian.
- 🧭 **A missing harness, as you asked.** `ctxray test` without `--layer` skips the layers a missing harness would run and names the `ctxray harness add` that adds it. With `--layer L4` or more, it fails, since you asked for those layers.
- 🔌 **`ctxray mcp add <agent>` connects it.** One command adds ctxray to Claude Code, Codex, Gemini CLI, OpenCode, or Cursor CLI, globally or with `--project` for one project, and a second run changes nothing. Run in a terminal, `ctxray mcp` prints these commands instead of waiting in silence.
- 🗑️ **spectate is gone.** Only `/ctxray` in Claude Code used it for real, so the command, its hooks for Claude Code and Cursor, and its readers for the other harnesses went. `/ctxray` works as before. The hooks `ctxray spectate install` left in `~/.claude/settings.json` and `~/.cursor/hooks.json` now do nothing: remove the entries that run `__spectate-hook` when convenient.
- 🧪 **Experimental says so.** A layer a harness has only as an experiment, like Cursor CLI's L4 to L7, is skipped with the config switch that turns it on, not with “needs mode:capture”.
- ✂️ **Five harnesses, not seven.** `claude-code-desktop` and `cursor-ide` are gone: they only read the same files as Claude Code and Cursor CLI and could never be launched. Use `claude-code` and `cursor-cli` in their place.
- 🧰 **Codex on a real model.** A Codex scenario can now change files in its copy of the project, where it used to run read-only. A skill Codex reads through the shell, with `cat` or `sed` on its `SKILL.md`, counts as loaded, so L6 and L7 see it. A skill read twice shows once, with the tokens of both reads.
- 📜 **Skill listings as the harness cuts them.** Claude Code gives its skill listing 1% of the model's window and leaves the skills that don't fit with their name only. Codex gives it 2% and cuts every description short. L3 now lists skills the same way, marks each one the budget cut, and the new `skill-listing` check warns before the model loses them. The rules match captured requests of Claude Code 2.1.328 and Codex 0.171 line by line.
- 🩻 **A tidier `/ctxray`.** The report writes the project as `~/…`, folds the skills that ship with Claude Code into one line, and before the session's first request asks you to ask something instead of failing.
- 🚦 **One harness session at a time.** L6 and L7 used to run four sessions of a harness side by side, which OpenCode or Cursor CLI turned into 2.5 GB. Now they run one after another, so 1 GB holds any run. `concurrency` in the config, `--concurrency`, or `CTXRAY_CONCURRENCY` lets more go at once, and a harness's own `concurrency` caps it lower.
- ⚡ **Large repositories open faster.** ctxray asks git for untracked files once and resolves symlinks only for agent files: `inspect` on an 87,000-file monorepo takes 5 s instead of 8, and a quarter of the CPU time.
- 📁 **`--report-dir` takes an absolute path.** `ctxray test --report-dir /tmp/out` writes to `/tmp/out`, not to `tmp/out` inside the project.
- ❓ **`ctxray help`.** `ctxray help` prints the list of commands, and `ctxray help diff` the page of one, the same as `--help`. It used to say “Unknown command”.
- 🗂️ **`harness remove` and `cache clear`.** `ctxray harness remove codex` unpins a harness from `ctxray.lock` and warns when the config still names it. `ctxray cache clear` lists every build in the cache, pinned ones too, and `--yes` removes them.
- 🩺 **`ctxray doctor --fix`.** It creates the cache folder and installs the harnesses `ctxray.lock` pins, then lists what it fixed and what's left to you: git, the network, proxies, CA certificates, Node, and keys.
- 📉 **`ctxray diff --file report.json`.** It compares the loadout with a saved report, from a past run or a CI artifact, instead of a git revision. Every report now keeps the loadout L3 predicts at the root for each harness. `diff` also writes `diff.json` and `diff.html` into the report folder, and the HTML report's diff tab lines its rows up again.
- 🧹 **No leftovers after a capture.** ctxray ends the harness's whole process group, so Cursor CLI's helpers no longer pile up over hundreds of sessions.

## 0.1.0

The first release. ctxray shows what your AI agents load into a model's context and tests it in CI.

- 🔍 **`ctxray inspect` shows what loads here.** Rules, skills, commands, and MCP servers of Claude Code, Codex, Gemini CLI, OpenCode, and Cursor CLI, each with its tokens and the reason it loaded: always, for a file path you pass with `--files`, or by its description. Claude Code Desktop and the Cursor editor read the same files, ask for them with `--harness`. A warning names what one agent sees and another doesn't, like a `CLAUDE.md` Codex never reads.
- 🪙 **Tokens counted each agent's way.** Claude's count comes from o200k with factors measured on `claude-sonnet-5-5`, Gemini's from the Gemma vocabulary, the others' from o200k. Every local count carries ≈. With `exactTokens`, ctxray asks the provider for the exact number through your key.
- ✅ **Tests in seven layers.** `*.ctxray.ts` files hold `test.resolve`, `test.assemble`, `test.wire`, `test.activate`, and `test.scenario`, from what the files predict (L3) to a task the agent solves end to end (L7). ctxray runs L1 Lint and L2 Policy itself. `ctxray init` writes a config and a first test that passes.
- 🧪 **One test, every agent.** A test runs once per harness in the config, and `expect.on` narrows a check to some of them. `discover.rules()` turns one test into one per rule, by CODEOWNERS owner, folder, or activation.
- 🎯 **Does the model pick the right skill?** `test.activate` sends prompts to a real model several times and checks the share of runs that loaded the skill, with a 95% Wilson interval. By default a skill must load in 80% of the runs, and a test makes the 16 runs it takes to prove that. The config's `activate` sets both for your project. Too few runs to tell gives `inconclusive`, not a guess. `--record` keeps the model's answers, and `--backend replay` plays them back for free on every merge request. `ctxray gen-prompts` writes prompts from the descriptions for you to review.
- 🛰️ **What the agent really sent.** L4 and L5 launch the agent on a copy of your project behind ctxray's proxy, with an isolated home, no network but the proxy, and a mock model: free and the same every run. You see the system prompt, the built-in tools, and every MCP tool with its schema's tokens.
- 📦 **Pinned agents.** `ctxray harness add` pins versions in `ctxray.lock` with integrity for every platform, and CI installs exactly those from npm or your registry. `harness upgrade` shows how a new version changes the context. `harness pack` and `install --from` carry them into a network without internet.
- 📋 **Your organisation's rules.** Policies limit tokens per component, ban or require MCP servers, and require files. `extends` shares them from an npm package. `ctxray baseline` lets an old repository adopt ctxray and fail only on new problems. 27 lint checks catch broken frontmatter, dead rules, missing imports, and skills an agent never sees.
- 📉 **What a merge request changes.** `ctxray diff` compares the loadout with `origin/master` or the `--base` you name.
- 👀 **Your own sessions.** `ctxray spectate install` adds hooks to Claude Code and Cursor, and `ctxray spectate` shows what your latest sessions loaded. Prompts never get stored.
- 🧩 **A plugin for Claude Code.** `/ctxray` shows what the current session loaded, `/ctxray-test` runs the tests, and the `write-tests` skill writes them. `ctxray mcp` serves `inspect`, `run`, and `diff` to any agent.
- 📊 **Reports.** A live view in the terminal, an HTML report in English and Russian that `ctxray show-report` keeps live while tests run, JUnit, Allure, JSON, and a Markdown summary that lands in the GitHub job summary.
- 🏢 **Closed networks.** LLM gateways, proxies, your CA certificates, internal npm registries with `.npmrc` auth, read-only shared harness caches, and an `offline` switch. `ctxray doctor` checks all of it first.
- 🔒 **Secrets stay out.** Keys, tokens, emails, phone and card numbers are hidden before anything reaches a trace, a report, a snapshot, or a cassette, with gitleaks' rules on top of ctxray's own.
- 🚚 **Install it your way.** npm, Homebrew, Scoop, `install.sh` and `install.ps1`, Docker images on ghcr.io, a GitHub Action, a GitLab CI template, and release archives that work as offline bundles. Executables for Linux (glibc and musl, x64 and arm64, and x64 without AVX2), macOS, and Windows on x64 and arm64. Checksums are signed with Sigstore and the files carry build attestations and an SBOM.
- 🌍 **English and Russian.** ctxray follows your system's language, or `--lang`.
